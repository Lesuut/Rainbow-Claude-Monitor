# System Monitor

Локальная HTML-панель: нагрузка ПК + лимиты трёх аккаунтов Claude.

## Зачем

У пользователя 3 аккаунта Claude, запускаются ярлыками с рабочего стола
(`Claude Personal 1.exe`, `Claude Personal 2.exe`, `Claude Work.exe`).
Каждый ярлык подставляет свой `CLAUDE_CONFIG_DIR`. Нужно одним взглядом видеть:
на каком аккаунте ещё остался лимит и не задыхается ли машина.

## Состав

| Файл | Роль |
|---|---|
| `server.ps1` | локальный HTTP-сервер (`HttpListener`, `127.0.0.1:8777`): отдаёт страницу и JSON |
| `index.html` | вся морда: 2 круглые шкалы + 3 карточки аккаунтов |
| `System Monitor.bat` | запуск сервера скрыто + открытие браузера (лежит в автозагрузке) |
| `poke.ps1` | пишет текст или клавиши в консоль чужого процесса (`WriteConsoleInput`) |
| `launch-color.ps1` | ждёт только что открытое окно, жмёт в нём Down+Enter и просит покрасить |
| `colors.json` | текущий акцент каждого аккаунта |
| `PROJECT.md` | этот файл |

Внешних зависимостей нет: только Windows PowerShell 5.1 + браузер.

Морда рассчитана на экран **960×640** и не прокручивается: `100vh`, grid из
четырёх строк, `overflow:hidden`. Минимальный кегль на странице — 14px.

## Откуда данные

### Железо (опрос раз в секунду)
- CPU % — `Win32_PerfFormattedData_PerfOS_Processor` (`Name='_Total'`)
- RAM — `Win32_OperatingSystem`: `TotalVisibleMemorySize` / `FreePhysicalMemory`
- Плюс: модель CPU, число ядер, uptime, число процессов

CIM-счётчик выбран вместо `Get-Counter`, потому что не требует секунды на семпл —
опрос мгновенный, шкалы обновляются плавно.

### Лимиты Claude

Два источника, в таком порядке.

**1. Живой запрос (основной).** `GET https://api.anthropic.com/api/oauth/usage`
с OAuth-токеном аккаунта. Токен читается из `%USERPROFILE%\<config>\.credentials.json`
в момент запроса, нигде не сохраняется и не логируется. Заголовки:

```
Authorization: Bearer <token>
anthropic-beta: oauth-2025-04-20
Accept: application/json
User-Agent: claude-cli/<ver> (external, cli)
```

Опрос раз в 2 минуты на аккаунт; после ошибки — пауза 10 минут. `server.ps1`
перебирает три набора заголовков и запоминает сработавший (`$hdrStyle`).
Ответ содержит `five_hour` / `seven_day` с полями `utilization` и `resets_at`.

**2. Кэш (запасной).** `%USERPROFILE%\<config>\.claude.json`, ключ
`cachedUsageUtilization` — та же структура плюс `fetchedAtMs`. Этот кэш пишет
только сам Claude Code при вводе `/status`, поэтому он часто устаревает на сутки.
Используется, если живой запрос не прошёл; страница тогда подписывает карточку
«кэш · N назад».

Поле `source` в `/api/stats` говорит, что сработало: `api` или `cache`.
Диагностика живого опроса — `GET /api/debug` (коды ответов и ошибки, без токенов).

### Работает ли Клод прямо сейчас

`%USERPROFILE%\<config>\sessions\<pid>.json` — реестр живых сессий, который ведёт
сам Claude Code. Нужны поля `pid`, `status` (`busy` во время хода, `idle` в
ожидании ввода) и `updatedAt`. Файлы переживают падение процесса, поэтому сессия
считается живой только если pid ещё есть в `Get-Process` и `updatedAt` моложе 12 ч.
Аккаунт горит, если занята хотя бы одна его сессия.

### Закат

`GET https://api.sunrise-sunset.org/json?lat=50.4501&lng=30.5234&formatted=0&date=<today>`
— Киев, запрашивается раз в сутки, отдаётся клиенту как `sun.sunriseMs` /
`sun.sunsetMs` в UTC. Если запрос не прошёл, клиент откатывается на 06:00 / 21:00
по местному времени ПК.

## Темы

Две палитры по 13 токенов (`DAY` и `NIGHT` в `index.html`). На экране всегда
их смесь: одно число `night` 0…1 гоняется через `lerp` по всем токенам и пишется
в CSS-переменные на каждом кадре. Поэтому сумерки — это дрейф, а не переключение.

Режимы — тумблер в шапке: слева светлая, по центру авто, справа тёмная. Выбор
лежит в `localStorage["sysmon-theme"]`. В авто: полная ночь до рассвета и после
заката, день между, с 45-минутной растяжкой на каждом краю. Для Киева 28 августа
(закат 19:53) это даёт 0.00 в 19:53, 0.49 в 20:15 и 1.00 к 20:38.

## Цвета аккаунтов

Хотелось брать цвет из команды `/color` в самом Claude Code. **Нельзя**: она
меняет цвет только в памяти запущенного окна и никуда его не пишет. Проверено
и по диску, и по докам:

- `sessions/<pid>.json` — 20 полей, цвета нет
- `.claude.json`, `settings.json`, `session-env/<id>/` — пусто
- statusline получает `session_name`, но поля цвета в схеме нет —
  <https://code.claude.com/docs/en/statusline>
- запрос на `color` в `settings.json` висит открытым —
  <https://github.com/anthropics/claude-code/issues/50393>,
  <https://github.com/anthropics/claude-code/issues/58588>

Поэтому цвет держит сама панель: `colors.json` рядом с `server.ps1`,
`{ personal1, personal2, work }` → одно из девяти имён, тех же, что у `/color`:
`red orange yellow green cyan blue purple pink default`. Меняется кликом по
кружку слева от имени аккаунта, пишется через `POST /api/color?id=&name=`.
Неизвестное имя или id сервер отклоняет с 400.

В `index.html` каждое имя задано дважды — `COLOR_DAY` (притемнённое, для бумаги)
и `COLOR_NIGHT` (яркое, для тёмной панели). Между ними едет тот же ночной
коэффициент, что и вся палитра, так что любой выбранный цвет автоматически
попадает в гамму обеих тем.

Соответствие ярлык → каталог (из `~/.claude/launchers/build_exes.ps1`):

| Ярлык | Config dir | Цвет |
|---|---|---|
| Claude Personal 1 | `.claude_personal` | синий |
| Claude Personal 2 | `.claude_personal2` | зелёный |
| Claude Work | `.claude_work` | оранжевый |

## Что происходит по кнопке Launch

`POST /api/launch?id=` стартует ярлык аккаунта из `%USERPROFILE%` и сразу
отпускает цикл сервера: ожиданием занимается отдельный процесс
`launch-color.ps1`. Кнопку можно жать сколько угодно раз подряд — на каждое
нажатие свой ждущий процесс, а `.claims/<pid>.claim` (создаётся `CreateNew`,
то есть атомарно) не даёт двум ждущим схватить одно окно.

Ждущий ищет **процесс**, а не сессию: `claude.exe`, чей родитель — ярлык этого
аккаунта, и который стартовал уже после самого ждущего. По сессии искать
нельзя — `sessions/<pid>.json` появляется только после ответа на вопрос о
доверии к папке, а именно его окно и ждёт.

Дальше: пауза 4 с на отрисовку TUI → `poke.ps1 -Keys "down,enter"`, то есть
«Yes, I trust this folder» → ждём появления сессии → `POST /api/color` с `pid`,
чтобы покрасилось ровно это окно, а не все окна аккаунта. Если сессия уже есть
(папка была доверена раньше), клавиши не шлются: строка ввода живая, и Down с
Enter ушли бы в разговор.

Сервер при старте вычищает из своего окружения всё `CLAUDE*` и `AI_AGENT`.
Иначе, если панель запущена из-под самого Claude Code, новое окно наследует
`CLAUDE_CODE_CHILD_SESSION` (не пишет сессию — панель его не видит и не красит)
и `CLAUDE_CONFIG_DIR` от чужого аккаунта.

## Важные оговорки

`/api/oauth/usage` — внутренняя ручка Claude Code, не публичный API. Она может
поменяться без предупреждения. Поэтому запрос обёрнут: любая ошибка тихо роняет
аккаунт на кэш `.claude.json`, страница продолжает работать, а причина видна
в `/api/debug`.

Проценты «стареют вперёд»: если `resets_at` уже прошло, окно считается
сброшенным и показывается как 0 % с подписью «свободно». Для живого источника
это почти не срабатывает, для кэша — постоянно.

## Как гонять

```
"System Monitor.bat"   # запустить и открыть браузер (он же в автозагрузке)
```
или вручную:
```
powershell -ExecutionPolicy Bypass -File server.ps1
```
Затем http://127.0.0.1:8777

Порт меняется в начале `server.ps1` (`$Port`).

## API

- `GET /` — страница
- `GET /api/stats` — `{ cpu, ram, host, accounts[] }`, у аккаунта есть `source: api|cache`
- `GET /api/debug` — что вернул живой опрос лимитов (без токенов)
- `POST /api/refresh` — сбросить кэш живого опроса и перезапросить
- `POST /api/launch?id=<personal1|personal2|work>` — запустить соответствующий .exe
